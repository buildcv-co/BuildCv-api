### SUGGESTION (nice to have, not blocking)
1. **ARCO anonymization legal review** — proposal Open Q #1. The current implementation (`[deleted]@anonymized` + `[Deleted User]` + `redacted`) is a clean interpretation of Art. IX + DIAN legal hold, but is not lawyer-reviewed. Defer to a future change with explicit user approval.
2. **Web JWT-in-cookie flow** is not fully wired end-to-end. The BFF routes use `cookie: request.headers.get("cookie") ?? ""` passthrough, but the browser auth (NextAuth.js cookie) and the backend JWT are two separate credentials. This is documented in PR3 risks and deferred.
3. **Refund mid-stream boundary** — R3's "no refund after first token" is enforced by architecture (refund handler called on `AI_UNAVAILABLE` before the stream starts), not by an explicit test. Adding a test that simulates a mid-stream failure and asserts no refund would be defense-in-depth.
4. **R3's "no refund mid-stream"** could be made testable by extracting a `RefundOnFailureHandler` boundary at the start vs after-first-token. Not required for v1.
