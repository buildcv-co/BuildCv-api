# 013.1 — Checklist Revisión Legal ARCO

## Status
[Spec] — Pendiente de sign-off por abogado colombiano

## Contexto

La feature 013-credit-consumption (tag `013-credit-consumption-v1.0`) implementó el derecho ARCO (Acceso, Rectificación, Cancelación, Oposición) bajo la Ley 1581 de 2012. La implementación anonimiza al usuario pero retiene facturas DIAN por obligación tributaria.

Esta checklist es para que el abogado colombiano valide la implementación **antes del rollout a producción**.

## Implementación actual

### Datos que se ANONIMIZAN al ejecutar ARCO

| Campo | Valor original | Valor anonimizado |
|-------|----------------|-------------------|
| `users.email` | usuario@gmail.com | `[deleted]@anonymized` |
| `users.name` | Juan Pérez | `[Deleted User]` |
| `users.provider_id` | google-oauth2\|123456789 | `redacted-{userId}` |
| `credit_ledger_entries` | (todas las filas del user) | **CASCADE-DELETE** (FK CASCADE) |

### Datos que se RETIENEN (DIAN Ley 1819 de 2016)

| Tabla | Por qué se retiene | Período |
|-------|---------------------|---------|
| `payments` | Obligación DIAN de conservar comprobantes de pago | 5 años (asumido, confirmar) |
| `invoices` | Obligación DIAN de conservar facturas electrónicas | 5 años (asumido, confirmar) |

### Branching en `DeleteUserDataHandler`

```csharp
if (await userDataStore.HasPaymentsAsync(userId, ct))
{
    // Usuario con pagos → ANONIMIZAR (DIAN legal hold)
    await userDataStore.AnonymizeAsync(userId, ct);
}
else
{
    // Usuario sin pagos → HARD-DELETE
    await userDataStore.DeleteAsync(userId, ct);
}
```

## Preguntas abiertas para el abogado

1. **`[deleted]@anonymized` como anonimización — ¿suficiente?**
   - ¿O requiere hash irreversible (ej. SHA-256 del user_id)?
   - ¿O eliminación completa del campo (NULL)?

2. **`provider_id` — ¿debe anonimizarse también?**
   - Actualmente se redacta a `redacted-{userId}`
   - Google/LinkedIn no requiere retención de provider_id

3. **`created_at` en user row anonimizado — ¿se preserva?**
   - Sí, actualmente. ¿Es aceptable o debe eliminarse para evitar inferencia temporal?

4. **Período de retención de facturas DIAN**
   - Asumimos 5 años (contabilidad + impuestos)
   - **¿Confirmar período exacto según normativa colombiana vigente?**

5. **Cascada del ledger**
   - `credit_ledger_entries` se elimina con el user (FK CASCADE)
   - ¿Aceptable? El ledger es trazabilidad interna, no factura fiscal
   - Alternativa: anonimizar ledger entries también (no eliminarlas)

6. **Notificación al usuario antes de ejecutar**
   - ¿Requiere confirmación por email antes de ejecutar ARCO?
   - ¿Plazo de gracia (ej. 15 días) entre solicitud y ejecución?

7. **Re-registro del mismo email**
   - Si el usuario se vuelve a registrar con el mismo email después de ARCO
   - ¿El sistema debe detectarlo y rechazar? ¿O es legítimo nuevo usuario?
