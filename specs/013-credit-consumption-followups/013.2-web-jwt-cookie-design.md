## Pre-design decision (owner-approved)

> **Owner chose Option B (NextAuth.js) over Option A (cookie-based, no new deps).** This design therefore **REWRITES** the previous design (Option A) to use NextAuth as the Web auth provider, with the backend exposed via a thin `/api/v1/auth/session` endpoint that exchanges a NextAuth-signed JWT for a backend-signed access JWT.

| Option | Mechanism | New deps | Pros | Cons |
|---|---|---|---|---|
| **A (rejected)** | Backend-signed `buildcv_session` HttpOnly cookie; BFF forwards cookie | 0 | 0 deps; ~120 LoC | BFF owns cookie format; manual CSRF; manual rotation; non-standard |
| **B (chosen)** | `next-auth@^4` JWT session; backend `/api/v1/auth/session` exchanges NextAuth JWT → backend JWT | `next-auth` (~50 KB gzip) | Industry-standard CSRF + rotation + secure cookies; ~200 LoC saved vs custom impl; multi-provider ready | +1 dep; lock-in to NextAuth API (stable, well-documented) |

**Constitution alignment** (Art. VI — "No sobre-ingeniería: un patrón solo cuando paga su costo"): the cost of `next-auth` is justified by the value — battle-tested CSRF/rotation/cookie handling, plus a one-line extension to add Apple/Microsoft/GitHub providers later. **AMENDMENT documented below.**

## Architecture overview

**Goal**: close the auth gap so a browser user signed-in via Google/LinkedIn OAuth can call `/api/credits/*`, `/api/payments/*`, and `/api/v1/adapt` end-to-end without manual JWT handling or test-only mocks.

**Flow (Option B — NextAuth.js)**:

```
┌────────┐  1. Click "Sign in with Google"  ┌────────────────────────────┐
│Browser │ ───────────────────────────────►  │ NextAuth API route         │
│        │ ◄── 302 to Google OAuth          │ /api/auth/[...nextauth]    │
│        │                                   └────────────────────────────┘
│        │  2. Google callback
│        │ ───────────────────────────────►  ┌────────────────────────────┐
│        │ ◄── 302 to / with Set-Cookie:     │ NextAuth signs JWT         │
│        │     next-auth.session-token       │ (HttpOnly, Secure,         │
│        │     (HttpOnly, SameSite=Lax)      │  SameSite=Lax)             │
└────────┘                                   └────────────────────────────┘
     │
     │ 3. Browser calls BFF /api/credits/balance
     │    Cookie: next-auth.session-token=<nextauth-jwt>
     ▼
┌──────────────────────────────────────────────────────────────────────┐
│ BFF route handler                                                     │
│   1. getServerSession(authOptions) → { user.id, jwt }                 │
│   2. cache hit (TTL 5 min)? → reuse backend JWT                       │
│   3. cache miss → GET /api/v1/auth/session                            │
│        Header: Authorization: Bearer <nextauth-jwt>                   │
│                  │                                                    │
│                  ▼                                                    │
│   4. Backend validates NextAuth JWT (shared HS256 secret),            │
│      looks up user, signs backend JWT (15 min), returns it            │
│   5. GET /api/v1/credits/balance                                      │
│        Header: Authorization: Bearer <backend-jwt>                    │
│   6. Return upstream response to browser                               │
└──────────────────────────────────────────────────────────────────────┘
```

**Why this split (Web session + backend access JWT)**:
- **Backend is the only source of truth for user identity** (Art. IX ✅ — ARCO deletion instantly invalidates backend JWT issuance).
- **Web never holds signing material** — only NextAuth knows the shared HS256 secret for session JWTs; backend has the same secret for validation.
- **Defense in depth**: NextAuth handles browser-side concerns (CSRF, cookie rotation, same-site); backend handles server-side concerns (token validation, user lookup, short-lived access JWTs).
- **Future-proof**: adding a third OAuth provider is one line in NextAuth config (Art. VI ✅).

**Why not option A (rejected)**: 200+ lines of custom session management code, manual CSRF tokens, manual rotation — all reinventing what NextAuth ships for free.

## Art. VI Amendment (Documented)

**Change**: Adding `next-auth@^4.24.7` as new runtime dependency in `BuildCv-web/package.json`.

**Justification** (per Constitution §Gobernanza → Proceso de enmienda):

1. **Cost-benefit**: Re-implementing CSRF tokens, secure cookie attributes, JWT rotation, and sign-in/sign-out flows correctly takes ~200 LoC and ~3 days of security review. NextAuth provides all of this, audited by thousands of projects, in one dependency (~50 KB gzipped).
2. **Robustness**: Custom session management is the #1 source of CVEs in Node.js apps (session fixation, CSRF bypass, cookie theft via XSS). NextAuth has these mitigations built-in and continuously patched.
3. **Constitution compliance**: Art. VI says "un patrón solo cuando paga su costo". The dep cost is 1 package + ~5 config lines; the value is eliminating a class of security bugs and ~200 LoC of custom code.
4. **Future scalability**: Adding more OAuth providers (Apple, Microsoft, GitHub) is one-line in NextAuth config, vs. a new OAuth handler per provider in custom code.

**Trade-offs**:
- **Pro**: ~200 LoC saved in custom session/CSRF code; multi-provider ready; industry-standard patterns.
- **Pro**: Built-in session rotation (auto-refresh within window).
- **Con**: +1 dependency (~50 KB gzipped, well-maintained, MIT license).
- **Con**: API lock-in to NextAuth (mitigated: NextAuth is stable, v4 has been the standard for 4+ years, v5 maintains similar API).

**Amendment process**:
1. ✅ **Proposal**: this design documents the change.
2. ✅ **Impact declared**: `BuildCv-web/package.json` adds dep; no backend changes besides new endpoint; no spec changes.
3. ⏳ **Owner approval required** (per §Gobernanza): pending ratification.
4. ⏳ **Registration**: upon approval, constitution goes 1.1.0 → 1.2.0 (MENOR — adding an exception to the "no new deps" rule, scoped to auth/session libraries with explicit justification).

**Fallback**: if owner rejects, revert to Option A design (582 lines, cookie-based, 0 new deps) and skip the constitution amendment.

## API layer (backend)

### New endpoint: `GET /api/v1/auth/session`

**File**: `BuildCv-api/src/BuildCv.Api/Endpoints/SessionEndpoint.cs` (NEW)

```csharp
using System.IdentityModel.Tokens.Jwt;
using System.Security.Claims;
using System.Text;
using BuildCv.Application.Abstractions;
using BuildCv.Infrastructure.Auth;
using Microsoft.IdentityModel.Tokens;

namespace BuildCv.Api.Endpoints;

public static class SessionEndpoint
{
    public static IEndpointRouteBuilder MapSessionEndpoint(this IEndpointRouteBuilder app)
    {
        app.MapGet("/api/v1/auth/session", async (
                HttpContext httpContext,
                IUserDataStore userStore,
                JwtTokenAdapter jwtAdapter,
                IConfiguration configuration,
                CancellationToken ct) =>
            {
                var authHeader = httpContext.Request.Headers.Authorization.ToString();
                if (!authHeader.StartsWith("Bearer ", StringComparison.Ordinal))
                {
                    return Results.Unauthorized();
                }

                var nextAuthJwt = authHeader["Bearer ".Length..].Trim();

                var userId = await ValidateNextAuthJwtAsync(nextAuthJwt, configuration);
                if (userId is null)
                {
                    return Results.Unauthorized();
                }

                var user = await userStore.GetByIdAsync(userId.Value, ct);
                if (user is null)
                {
                    return Results.Unauthorized();
                }

                var jwt = jwtAdapter.GenerateAccessToken(user.Id, user.Email);
                var expiresAt = DateTime.UtcNow.AddMinutes(15);

                return Results.Ok(new SessionResponse(
                    Jwt: jwt,
                    ExpiresAt: expiresAt,
                    User: new SessionUserInfo(user.Id, user.Email, user.Name)));
            })
            .WithName("GetSession")
            .WithSummary("Exchanges a NextAuth session JWT for a short-lived backend access JWT.")
            .Produces<SessionResponse>(200)
            .Produces(401);

        return app;
    }

    private static Task<Guid?> ValidateNextAuthJwtAsync(string jwt, IConfiguration configuration)
    {
        var jwtSettings = configuration.GetSection("JwtSettings").Get<JwtSettings>()
            ?? throw new InvalidOperationException("JwtSettings missing.");

        var tokenHandler = new JwtSecurityTokenHandler();
        var validationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidIssuer = jwtSettings.Issuer,
            ValidateAudience = true,
            ValidAudience = jwtSettings.Audience,
            ValidateIssuerSigningKey = true,
            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtSettings.Secret)),
            ValidateLifetime = true,
            ClockSkew = TimeSpan.FromMinutes(1)
        };

        try
        {
            var principal = tokenHandler.ValidateToken(jwt, validationParameters, out _);
            var subClaim = principal.FindFirst("sub")?.Value
                ?? principal.FindFirst(ClaimTypes.NameIdentifier)?.Value;
            return Task.FromResult(
                Guid.TryParse(subClaim, out var userId) ? userId : (Guid?)null);
        }
        catch
        {
            return Task.FromResult<Guid?>(null);
        }
    }
}

public sealed record SessionResponse(string Jwt, DateTime ExpiresAt, SessionUserInfo User);
public sealed record SessionUserInfo(Guid Id, string Email, string Name);
```

**Notes**:
- **Reuses existing `JwtTokenAdapter.GenerateAccessToken`** from 009-auth (no new crypto code, Art. VI ✅).
- **Reuses existing `IUserDataStore`** from 009-auth (no new port).
- **Shared HS256 secret** between NextAuth (signs session JWT) and backend (validates + signs backend JWT).
- **No rate limiting** on this endpoint — it only validates a signed JWT, abuse bounded by session TTL.

### NextAuth configuration (`BuildCv-web/lib/auth.ts` — NEW)

```typescript
import NextAuth, { type NextAuthOptions } from "next-auth";
import GoogleProvider from "next-auth/providers/google";
import LinkedInProvider from "next-auth/providers/linkedin";

const BACKEND_URL = process.env.BACKEND_URL ?? "http://localhost:5080";

export const authOptions: NextAuthOptions = {
  providers: [
    GoogleProvider({
      clientId: process.env.GOOGLE_CLIENT_ID!,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
    }),
    LinkedInProvider({
      clientId: process.env.LINKEDIN_CLIENT_ID!,
      clientSecret: process.env.LINKEDIN_CLIENT_SECRET!,
    }),
  ],
  session: {
    strategy: "jwt",
    maxAge: 7 * 24 * 60 * 60, // 7 days
  },
  jwt: {
    secret: process.env.NEXTAUTH_SECRET!,
  },
  callbacks: {
    async signIn({ user, account }) {
      const provider = account?.provider;
      const providerId = account?.providerAccountId;
      const email = user.email;
      const name = user.name;

      if (!provider || !providerId || !email) return false;

      const res = await fetch(`${BACKEND_URL}/api/v1/auth/${provider}/callback`, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ code: providerId, email, name }),
      });

      if (!res.ok) return false;

      const data = (await res.json()) as { userId: string };
      (user as { backendUserId?: string }).backendUserId = data.userId;
      return true;
    },
    async jwt({ token, user }) {
      const backendUserId = (user as { backendUserId?: string } | undefined)?.backendUserId;
      if (user && backendUserId) {
        token.sub = backendUserId;
        token.email = user.email ?? undefined;
        token.name = user.name ?? undefined;
      }
      return token;
    },
    async session({ session, token }) {
      if (session.user && token.sub) {
        (session.user as { id?: string }).id = token.sub;
      }
      return session;
    },
  },
  pages: {
    signIn: "/auth/signin",
  },
};

export default NextAuth(authOptions);
```

### JWT client (`BuildCv-web/lib/api/jwt.ts` — NEW)

```typescript
import { getServerSession } from "next-auth";
import { authOptions } from "@/lib/auth";

type CachedJwt = {
  jwt: string;
  expiresAt: number; // unix ms
};

const cache = new Map<string, CachedJwt>();
const TTL_MS = Number(process.env.JWT_CACHE_TTL_SECONDS ?? 300) * 1000;

type SessionPayload = {
  jwt: string;
  expiresAt: string;
  user: { id: string; email: string; name: string };
};

export async function getJwtFromSession(): Promise<
  { jwt: string; userId: string } | null
> {
  const session = await getServerSession(authOptions);
  if (!session || !session.user) return null;

  const userId = (session.user as { id?: string }).id;
  if (!userId) return null;

  const cached = cache.get(userId);
  const now = Date.now();
  if (cached && cached.expiresAt > now) {
    return { jwt: cached.jwt, userId };
  }

  const baseUrl = process.env.BACKEND_URL ?? "http://localhost:5080";

  const nextAuthTokenResponse = await fetch(`${baseUrl}/api/v1/auth/session`, {
    method: "GET",
    headers: {
      // NextAuth session JWT is stored in an HttpOnly cookie that the BFF
      // can read via cookies() — but getServerSession() returns it via the session object.
      // For server-to-server calls, we pass the NextAuth session token in the Authorization header.
      Authorization: `Bearer ${await getNextAuthTokenFromCookies()}`,
    },
    cache: "no-store",
  });

  if (!nextAuthTokenResponse.ok) return null;

  const data = (await nextAuthTokenResponse.json()) as SessionPayload;
  cache.set(userId, {
    jwt: data.jwt,
    expiresAt: new Date(data.expiresAt).getTime(),
  });

  return { jwt: data.jwt, userId };
}

async function getNextAuthTokenFromCookies(): Promise<string> {
  const { cookies } = await import("next/headers");
  const cookieStore = await cookies();
  const token =
    cookieStore.get("__Secure-next-auth.session-token") ??
    cookieStore.get("next-auth.session-token");
  if (!token) throw new Error("NextAuth session cookie missing.");
  return token.value;
}

export function clearJwtCache(): void {
  cache.clear();
}

setInterval(() => {
  const now = Date.now();
  for (const [key, value] of cache.entries()) {
    if (value.expiresAt <= now) cache.delete(key);
  }
}, 10 * 60 * 1000).unref();
```

import { NextResponse } from "next/server";
import { BACKEND_URL } from "@/lib/api/backend";
import { getJwtFromSession } from "@/lib/api/jwt";

export const dynamic = "force-dynamic";
export const runtime = "nodejs";

export async function GET() {
  const session = await getJwtFromSession();
  if (!session) {
    return NextResponse.json(
      { error: "AUTH/UNAUTHENTICATED" },
      { status: 401 },

    status: res.status,

      "content-type": res.headers.get("content-type") ?? "application/json",
    },
  });
}

## Failure modes & recovery

### 1. Shared secret mismatch (API ↔ Web)
- **Symptom**: backend `ValidateNextAuthJwtAsync` throws, returns 401.
- **Detection**: integration test `SessionEndpoint_Returns_401_When_Secret_Mismatch` (PR1).
- **Mitigation**: fail-fast startup check in `Program.cs`.
- **Recovery**: align `appsettings.json` `JwtSettings:Secret` with `NEXTAUTH_SECRET` env var.

### 2. NextAuth session expired
- **Symptom**: NextAuth cookie > 7 days old → `getServerSession()` returns null.
- **Detection**: Web test `getJwtFromSession_Returns_Null_After_Session_Expiry`.
- **Mitigation**: NextAuth auto-refreshes session if user is active within window.
- **Recovery**: browser redirects to `/auth/signin`.

### 3. Cache stale after NextAuth sign-out
- **Symptom**: user signs out → session cookie cleared → cache still holds JWT.
- **Detection**: Web test `getJwtFromSession_After_SignOut_Returns_Null`.
- **Mitigation**: on sign-out, NextAuth clears cookie + we call `clearJwtCache()` via `signOut` callback.
- **Recovery**: next BFF call returns 401 → browser redirects to sign-in.

### 4. Backend user deleted (ARCO)
- **Symptom**: NextAuth session JWT still valid, but backend `/api/v1/auth/session` returns 401.
- **Detection**: integration test `SessionEndpoint_Returns_401_When_User_Deleted`.
- **Mitigation**: existing flow handles this — user lookup fails → 401.
- **Recovery**: browser redirects to sign-in (Art. IX ✅).

### 5. NextAuth provider secret rotation
- **Symptom**: Google/LinkedIn client secret rotated, OAuth flow fails.
- **Mitigation**: standard OAuth secret rotation, no special handling needed.
- **Recovery**: update `GOOGLE_CLIENT_SECRET` / `LINKEDIN_CLIENT_SECRET` env vars.

### 6. Clock skew between API and Web
- **Symptom**: Web cache says "valid for 5 min" but backend says "expired".
- **Mitigation**: backend `ValidateToken` returns 401 (clock skew 1 min); Web catches 401, clears cache entry.

- Admin impersonation.
- Session analytics or tracking.
- Adding Apple/Microsoft/GitHub OAuth providers (NextAuth supports them; not needed for v1).
