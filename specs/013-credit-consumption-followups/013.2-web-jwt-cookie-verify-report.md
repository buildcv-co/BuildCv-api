### R3: JWT caching

- **Implementation**:

- **Status**: ✅ **PASS** — all spec scenarios covered including the "configurable TTL" requirement (test sets `JWT_CACHE_TTL_SECONDS=300`).

## Gaps identified

### CRITICAL (must fix before archive)

(none)

### WARNING (should fix but not blocking)

- **Art. III persistence violation** (pre-existing from `009-auth`) — `IUserDataStore` is real persistence (InMemory or Postgres via EF Core). Constitution Art. III says v0 MUST NOT persist. This was accepted for the v1 features (credits, payments, auth, ARCO) in `009-auth` but the corresponding Art. VI amendment was never ratified.
- **Art. VII auth middleware** (pre-existing from `009-auth`) — Authentication is required for v1 endpoints (`/api/credits/*`, `/api/payments/*`). v0's "no account required" flow is preserved (those endpoints return 401 when no session exists; users can still use `/api/score`, `/api/adapt`, `/api/export`, `/api/import` anonymously). Constitution Art. VII says v0 MUST be usable without account; v1 features may gate on auth. The boundary is implicitly v0-vs-v1 by endpoint, but no explicit amendment marks it.

### SUGGESTION (nice to have)

- E2E uses `encode()` from `next-auth/jwt` instead of real OAuth PKCE — documented workaround, identical to 012-wompi and 013-credit-consumption E2E suites. Future: add a stub OAuth provider in NextAuth config that the E2E tests can hit directly.
- Shared secret distribution (`NEXTAUTH_SECRET` ↔ `appsettings.json:NextAuth:SigningKey`) needs a production runbook (Render env var sync + rotation procedure). Not blocking, but should ship before public deploy.
- Constitution bump 1.1.0 → 1.2.0 should be executed (single-file PR to `.specify/memory/constitution.md`) to formally ratify the `next-auth` dep and the v0.5 → v1 persistence boundary.
